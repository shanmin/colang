# 函数定义

## 语法

```
[ public ] TYPE FUNCTION_NAME([TYPE ARG1, ...])
{
	segment
	return VALUE;
}
```

## 说明

（本节只描述函数对外的语义与行为；其内部实现机制不在本文范围。）

函数定义由四部分组成：返回类型 `TYPE`、函数名 `FUNCTION_NAME`、参数表、函数体。函数名在所在模块内唯一；`return VALUE;` 交出结果并结束调用。

### 返回类型

- 返回类型**必须显式书写**。Co 不接受早期 C 的“隐式 int”（省略类型即当作 `int`）的写法，缺少返回类型的函数定义会被拒绝。
- `void` 表示该函数不返回任何值。`void` 只能用作函数的返回类型，**不能**用作变量或形参的类型。
- 可返回整数、浮点、指针、struct 值、class 引用等类型；不能把数组作为结果直接返回（需要返回聚合时用 struct 承载，或交出指针）。

### 参数

- 每个形参写成 `TYPE ARG_NAME`，多个形参用逗号分隔。
- 不接收参数时，参数表写 `()` 或 `(void)`，两者同义；调用时不得带实参。
- 形参是函数内部的局部变量：作用域只在函数体内，与外部的同名变量互不干扰。
- 数组形参按指针处理：`int a[]`、`int a[10]` 都等价于 `int *a`，函数体内 `sizeof(a)` 得到的是指针宽度而非数组长度。
- 变参函数以 `...` 结尾，配合 `<stdarg.h>` 的 `va_start` / `va_arg` / `va_end` 读取。
- 不支持默认参数值，也不支持引用形参（如 `int &x`）。调用一律按值传递；需要让函数改动调用方的数据，就传入指针。

### 可见性与导出

`public` 是 Co 唯一的可见性关键字（没有 `private`，也不另设 `export`），它同时承担“模块接口”与“动态库导出”两种语义：

| 写法 | 含义 |
| --- | --- |
| `[ public ]` | 函数进入所在模块的对外接口，可被其他模块使用；生成动态库时进入导出表 |
| 省略 `public` | 函数只在定义它的模块内部可见，其他模块取不到，也不导出 |

### 定义顺序与递归

Co 不要求“先声明后使用”：同一模块内的函数可以互相引用，**与书写顺序无关**，因此递归、以及两个函数相互调用（互递归）都无需写前置声明。写前置声明（原型）同样允许，原型里的参数名可以与定义里的不同。

### 返回与 `return`

- 返回类型非 `void` 的函数，函数结束必须给出返回值。
- 返回类型为 `void` 的函数，可以完全不写 `return`；也可以在中途写一条裸 `return;` 提前结束。
- 在函数体内，`return` 只结束其所在函数。顶层（文件作用域）`return`、进程退出码与程序执行顺序属程序级模型，见「程序入口与执行」章节。
- `void` 函数不得 `return 值`；非 `void` 函数不得写裸 `return;`。这两类写法编译器都会拒绝。
- 一个函数体内允许出现多条 `return`（常用于条件早退）。

### 示例

下例涵盖：`public`、`void`、递归、变参，以及“定义在后、调用在前”的书写顺序：

```
#include <stdarg.h>

public int add(int a, int b)
{
    return a + b;
}

void greet()
{
    printf("hello\n");            // void 函数，不写 return
}

int fact(int n)
{
    if (n <= 1)
        return 1;                 // 条件早退
    return n * fact(n - 1);       // 递归
}

int total(int n, ...)
{
    va_list ap;
    int i;
    int s = 0;
    va_start(ap, n);
    for (i = 0; i < n; i++)
        s = s + va_arg(ap, int);
    va_end(ap);
    return s;
}

// 使用在定义之前也可以，只要在同一模块内
printf("%d\n", add(1, 2));            // 3
greet();                               // hello
printf("%d\n", fact(5));              // 120
printf("%d\n", total(3, 10, 20, 30)); // 60
```

### 与 C / C++ 的关系

| 方面 | Co | 相对语言 |
| --- | --- | --- |
| 形参类型化、按值传递、`return` | 沿用 | 与 C 相同 |
| `static` / `extern` 存储类、函数指针 | 沿用 | 与 C 相同 |
| 定义顺序 | 无关，可先调用后定义 | 与 C 不同（C 要求先声明） |
| 省略返回类型 | 不允许 | 与 C 相同（C99 起已取消隐式 int） |
| 空参数表 `()` | 即“不接收参数”，与 `(void)` 同义 | 与 C 不同（C 里 `()` 表示参数未指明） |
| 重载、默认参数、引用形参、函数模板 | 不提供 | 与 C++ 不同 |
| `public` | 表达“模块接口 / 导出”，而非访问区间 | 与 C++ 的 `public` 含义不同 |

> **兼容性告知**：Co 的 `()` 与 `(void)` 同义，都不接收任何实参。从 C 迁移时，凡是靠 `f()` “参数未指明、可传任意实参”这一习惯写下的代码，在 Co 中不成立。

### 当前边界（编译器实装状态）

自 **0.3.0** 起：

- **`public` 修饰顶层函数/全局变量已实装**：词法/语法/语义已接入，产物为动态库时写入导出表（`DLLExportStorageClass`）；`static public` 混序合法。**自 0.3.0 起 `public` 同时作为跨模块可见性的唯一闸门**：未标 `public` 的符号不可被 `import`（具名/star 命中均报 `cannot import non-public symbol`）；imported 非 `public` 符号在 codegen 强制 `InternalLinkage`。本批 `public` 仍 **不改变同 TU 内的 linkage**（非 public 默认仍为 ExternalLinkage，同 P211）；“模块内部”仍为**省略 `public`**（详见「模块」与「import」章节）。
- **顶层命令按顺序执行已实装**（入口分派、`main` 可选、顶层 `return` 与退出码）——完整模型见「程序入口与执行」章节。

### 保留名

`main` 及标准库已声明的函数名（如 `printf`）不应被自定义函数占用；Co 的四个生命周期协议名（`__new__`、`__retain__`、`__release__`、`__delete__`）为保留名，不得用作函数名。
