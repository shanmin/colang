# 编译器命令行

## 调用格式

```
colang [选项] <源文件.co>
```

一次调用处理**一个**源文件。不指定任何动作选项时，编译并链接为可执行文件。

## 选项

| 选项 | 说明 |
| --- | --- |
| `-h`, `--help` | 显示用法与选项列表 |
| `-v`, `--version` | 显示编译器版本、所用 LLVM 版本与目标平台 |
| `-E` | 仅做预处理，把展开后的 token 清单打到标准输出 |
| `-c` | 仅编译，产出 `.bc` 目标文件，不链接 |
| `-o <file>` | 指定输出文件 |
| `-I <dir>` | 追加头文件搜索目录，也可写作 `-I<dir>`；可重复给出 |

## 产物与默认名

| 动作 | 产物 | 未写 `-o` 时的默认名 |
| --- | --- | --- |
| 默认（编译 + 链接） | 可执行文件 | Windows：`<源文件名去扩展>.exe`；其他平台：`<源文件名去扩展>` |
| `-c` | `.bc` 目标文件 | `<源文件名去扩展>.bc`，留在当前目录 |
| `-E` | 标准输出 | 固定走标准输出，`-o` 对其无效 |

链接方式调用时，中间的 `.bc` 写在系统临时目录，链接完成后自动删除。

## `-E` 的输出形态

`-E` 打印的是**逐行 token 清单**，形如：

```
hello.co:3:1  keyword     int
hello.co:5:12  string      "hello\n"
```

它用于查看宏展开、条件裁剪与文件包含的结果，**不是**可以直接再交给编译器处理的 C 源码。此外 `-E` 到预处理为止即结束，不做语法检查：即使源文件存在语法错误，`-E` 仍会输出 token 并返回 0。

## 头文件搜索

按优先级从高到低：

1. 命令行 `-I` 给出的目录；
2. Co 自制标准头目录（`stdio.h`、`stdint.h` 等），由编译器自动定位：先读环境变量 `COLANG_STDLIB`（直接指向标准头目录）；未设置时，从 `colang` 可执行文件所在目录逐级上溯，以其中存在 `stdlib/include/stddef.h` 为标记定位到 `stdlib/include`。

发布包保持了上述相对布局，因此解压后可直接使用；把编译器挪到别处时，请保持 `bin/` 与 `stdlib/include/` 的相对位置，或改用 `COLANG_STDLIB` 指定。标准头定位不到时，`#include <stdio.h>` 会报 `#include file not found`。

## 链接前提：需要外部 clang

编译器产出的是 LLVM bitcode，把它变成可执行文件的那一步由外部 `clang` 完成。查找 `clang` 的顺序：

1. 从 `colang` 可执行文件所在目录逐级上溯，查找 `llvm*/build/Release/bin/`（其次 `Debug`）下的 `clang`；
2. 找不到则回退使用 `PATH` 上的 `clang`。

目标机上没有 `clang` 时，只有 `-E`、`-c` 这类不链接的动作可用；默认的编译 + 链接会失败并报 `linking failed`。

> **兼容性告知**：这一依赖是发布包运行环境的一部分。若要在未安装 LLVM 工具的机器上分发你用 colang 编译出的程序，需要分发的是**编译产物**，而不是 colang 本身。

## 多文件程序

一次调用只接受一个源文件，其余的位置参数若以 `.bc` 结尾，会被当作链接输入：

```
colang -c a.co                 # 产出 a.bc
colang -c b.co                 # 产出 b.bc
colang a.bc b.bc -o app.exe    # 把两个目标文件链接为可执行文件
```

未写 `-o` 时，纯链接动作的默认产物是 `a.exe`（Windows）/ `a.out`（其他平台）。模块机制（`import`）尚未开放，设计方向见「模块」与「import（模块导入）」章节。

## 诊断与退出码

诊断统一按 `文件:行:列: error: 说明` 的形式输出到标准错误（提示类为 `warning`）。退出码只有两种：成功 `0`，失败 `1`。

## 源文件

Co 源文件的默认扩展名为 `.co`（基于 web 页面时为 `.cop`）。文件若带 UTF-8 BOM，读取时会自动剥除。

## 当前边界

- `-h` 还会列出若干仅供编译器自身调试用的选项（token、语法树、IR 转储等）。这些选项的行为与格式不保证跨版本稳定，本文档不对它们作约定。
