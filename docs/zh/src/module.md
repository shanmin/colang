# 模块

> 自 **0.3.0** 起，Co 的模块系统随 `import`（`.co` 源合并）落地：一个 `.co` 文件即一个模块、`public` 同时充当**动态库导出**与**跨模块可见性**的唯一闸门、被导入模块的顶层裸代码在首次加载时按集中拓序执行一次。`.obj` / `.dll` / `.so` 作可导入模块仍归后续里程碑；模块别名限定访问 `m.f()` / `m.x` 亦归后续。

## 一个文件即一个模块

**一个 `.co` 源文件就是一个模块**。模块是 Co 组织程序、划定接口边界的基本单位：一个模块内定义的名称，默认属于该模块；要让别的模块使用，需显式标 `public`。

模块**默认以其文件的名称命名**（即去掉扩展名的文件名）；导入时可用 `as` 为它另起本地别名（本批已解析语法位、限定访问待后续）。加载阶段以**规范化绝对路径**（Windows 下大小写不敏感）作模块唯一 key，同模块被多处 `import` 只加载与拓入一次。

设置模块的目的在于支持大工程组织、并避免陷入 C/C++ 头文件（`.h`/`.cpp`）分离带来的重复定义与同步成本。

## 对外接口：`public`

- `public` 是 Co **唯一的可见性关键字**——没有 `private`，也不另设 `export`。它同时承担两件事：标记**模块接口**（可被其他模块 `import`）与**动态库导出**（写入 DLL 导出表）。
- 未标 `public` 的定义仅在模块内部可见；标了 `public` 才对外可见、才可被导入。
- `public` 可修饰顶层函数与全局变量；`class` / `struct` 及其成员的 `public` 修饰归 0.4.0。
- imported 的非 `public` 符号在 codegen 强制 `InternalLinkage`——同模块内部引用可解析，但不注入外部可见的 LLVM 值。

## 模块的形态

一个模块在物理上可以表现为不同的产物形态：

| 形态 | 说明 | 状态 |
| --- | --- | --- |
| `.co` | 源文件模块，最直接的形式 | **0.3.0 已落地** |
| `.obj` | 编译目标文件（`-c` 产物） | 归后续里程碑 |
| `.dll` / `.so` | 原生动态库 | 归后续里程碑 |

> **为何 `.obj`/`.dll` 作模块并非「拿来就能用」**：`import` 需要**编译期的声明信息**（函数原型、类型定义、哪些名字对外可见），而 `.obj`/`.dll` 本质是**链接期的符号定义**。要让一个二进制产物成为「可被导入的模块」，它必须**额外携带自身的接口/声明元数据**——这套载体基准与编译器都在后续里程碑定义。

## 顶层代码的执行模型

被导入模块的顶层裸代码遵循「**首次加载时执行一次** + **集中拓序**」：所有被 import 的模块的顶层代码统一在主源入口之前 emit、按依赖闭包的 DFS 后序排列（被依赖方先跑、依赖方后跑）；`import` 行的书写位置不影响执行时机。**非主模块的 `main` 不作为加载钩子**——若模块内定义了 `main`，它只是普通函数符号、不自动执行。详见「import（模块导入）」章节。

## 文件级 `static` 与「省略 `public`」的并存

自 0.3.0 起：
- **`public`** 管跨模块可见性——省略即「模块内部」、加了才可被 `import`；
- **`static`** 保留 C 语义——作本翻译单元内部链接位，与 `public` 互不冲突（`static public` / `public static` 混序均合法、语义为「对外导出、本 TU 内部链接」，实际产物中该符号仍属内部）；
- 基准中 `static` 未来仅作为类的静态成员修饰符（归 0.4.0 class 批次处理）。

## 尚未定稿

以下关键点归后续里程碑一并处理：

- 模块别名限定访问 `m.f()` / `m.x` 的完整语义（本批 `ModAlias` 语法位已解析但未启用）；
- `.obj` / `.dll` / `.so` 作可导入模块的声明元数据载体；
- 跨模块 `struct` / `enum` 类型引用（本批 `import` 主要面向函数、全局变量与顶层裸指令）；
- DLL 场景下 `DllMain` 合成与顶层段触发时机。

## 当前实装边界（0.3.0）

- **模块边界**：一个 `.co` 文件 = 一个模块；模块 key = 规范化绝对路径；跨文件同目录重名以路径唯一化区分。
- **`public`**：顶层函数与全局变量已可用；产物为动态库时写入导出表（`DLLExportStorageClass`）；本批 `public` **不改 linkage**（非 public 仍默认 ExternalLinkage、但 imported 非 public 会被 codegen strip 到 `InternalLinkage`）。
- **`static public`** 混序合法；语义与 P211 一致。
- **动态库产物**：无 `-shared` 选项，编译器按 `-o` 输出路径的扩展名自动切换 DLL / exe 链接模式；输出取为 `*.dll` 即产出含导出表的动态库（并随基名生成导入库 `*.lib`，Windows 实测）。
- **多文件程序**：经由 `import` 组合多个 `.co` 源文件（0.3.0 已可用）。`-c` 产出的单个 `.obj` 用于查看编译结果；把多个目标文件直接链接为可执行文件的能力尚在学习中（见「编译器命令行」章节）。
- **模块顶层代码执行**：见「import（模块导入）」章节；本批只覆盖 `.co` 消费路径。
