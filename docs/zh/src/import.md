# import（模块导入）

> **规划中特性，当前版本尚未开放。** 本章只记录语言基准里 `import` 的设计方向，不代表现装编译器已支持。当前 colang 处于「仅支持 C 编译」阶段，`import` 尚未实装，请在后续版本落地后再据实际行为使用。

## 用途

按基准设想，`import` 用于从其他模块（文件）导入名称，以支持大工程的组织与接口可见性，避免陷入 C/C++ 头文件分离带来的重复定义与同步成本。

## 设计方向（基准原文）

`Co程序设计` 对 `import` 只给出一条语法，尚无配套的语义约定。其中的「导入集合」有两种**互斥**形态——**列出若干具名项**（逗号分隔、可给别名）或**用 `*` 导入全部**；原文写在同一行、以 `|` 分隔，这里拆成两行以便阅读，语义不变：

```
import name [as aliasname], … from filename [as aliasname];
import * from filename [as aliasname];
```

各成分的含义：

| 成分 | 含义 |
| --- | --- |
| `name` | 要导入的名称 |
| `name as aliasname` | 给导入的名称起别名 |
| `…, …` | 逗号后可继续跟多个 `name [as aliasname]` 项 |
| `*` | 导入该来源的全部可导入名称 |
| `filename` | 来源模块的名称（可含路径） |
| `filename as aliasname` | 给来源模块起别名 |

## 为什么这里不给示例

`import` 的以下关键点在基准中都**尚未定稿**，任何示例都会变成对未拍板语法的承诺，故本章刻意留空：

- 导入名称的可见性规则（是否要求来源方显式标注对外可见、裸名能否跨模块使用）；
- 顶层代码在跨模块加载时的执行时机与次数；
- 模块名与路径的解析方式、环依赖的处理；
- 与 `public` / 动态库导出的交互边界。

这些要等 `import` 在当前代编译器实装时，连同语义一并定稿后再补写。

## 当前状态

- 现装编译器不识别 `import`：遇到源文件里的 `import … from …` 会把它当作文件作用域的未知词，报 `expected type specifier, got 'import'` 并终止，不产生任何模块导入效果。
- 现阶段多文件程序请改用编译期方式组织（`-c` + 链接；具体用法见「编译器命令行」章节的「多文件程序」）。
