# 程序入口与执行

> 本章描述 Co 的程序入口与执行模型。**入口分派、`main` 可选、顶层 `return` 与退出码自 V0.2.0 已实装；跨模块（`import`）顶层代码的集中拓序执行自 V0.3.0 已实装；Windows GUI 入口 `WinMain` 与 `[[subsystem("windows")]]` 子系统切换自 V0.3.1 已实装；顶层入口内建命令行参数 `argc`/`argv` 自 V0.5.5 已实装（见「命令行参数」）**。

## 顶层语句顺序执行

Co 的程序从「顶层」开始执行：一个 `.co` 文件里，写在函数、类型等定义**之外**的命令（顶层裸指令），**按它们在源码中出现的先后顺序**依次执行。你不必写一个 `main` 函数来充当入口。

## 有没有 `main` 都可以

为兼容 C 风格写法，Co 同时接受两种程序：

- **不写 `main`**：程序就是「顺序执行顶层语句」，执行完即结束。
- **写了 `main`**：`main` 是一个普通函数，在**所有顶层语句执行完之后**才进入它。

## GUI 入口（`WinMain`）

除「顶层语句 / `main`」这套控制台入口外，Co 还支持 Windows GUI 入口 `WinMain`：

```
int WinMain(void* hInstance, void* hPrevInstance, char* lpCmdLine, int nCmdShow)
{
    // 创建窗口、跑消息循环……
    return 0;
}
```

- **签名固定**：四个参数、返回 `int`（ANSI 版；宽字符版 `wWinMain` 暂未支持）。返回值即进程退出码。
- **定义 `WinMain` 即自动走 GUI 入口**：产物为 Windows GUI 子系统（无控制台窗口），无需命令行开关。
- 若想在保留 `main`/顶层入口的同时去掉控制台，可在入口函数上标 `[[subsystem("windows")]]`（见「属性」章节）。
- **`WinMain` 与顶层裸指令互斥**：同一文件里既有 `WinMain` 又有顶层裸指令，编译器报错（GUI 逻辑请写进 `WinMain`）；`WinMain` 形参个数须为 4，否则报错。

## 进程退出码

程序结束返回给操作系统的数（退出码）按下列规则确定：

| 情形 | 退出码 |
| --- | --- |
| 顶层执行到 `return V;` | `V`，并立即结束整个程序（其后的顶层语句与 `main` 都不再执行） |
| 顶层跑完没有 `return`，且有 `main` | `main` 的返回值 |
| 顶层跑完没有 `return`，且无 `main` | `0` |
| 裸 `return;`（不带值） | `0` |

要点：**顶层的 `return` 结束的是整个程序**（不是某个函数），因此它会**跳过 `main`**；函数体内的 `return` 仍只结束它所在的函数（见「函数定义」章节）。

## 命令行参数

自 **V0.5.5** 起，`.co` 顶层入口（**不写 `main`**、由编译器合成控制台入口的场景）可直接引用两个编译器**内建名** `argc` 与 `argv`：

- `argc` 是 `int`，为参数个数（含程序名本身，故 `argc >= 1`）；
- `argv` 是 `char**`（字符串指针），`argv[0]` 通常是程序自身的路径，其后依次是各参数；
- 遍历以 `argc` 计数为准；`argv[argc]` 恒为 `NULL`（C 语言保证）。`argv` 是**裸指针**、**不带长度属性、无越界检查**（C 语义），越界需自行用 `argc` 约束；
- 二者作用域**限于合成入口的顶层代码**：在 `.c` 文件、动态库（`-o *.dll` / `*.so`）产物、或 GUI `WinMain` 入口下引用 `argv`，编译器按「未声明标识符」报错。

```
// hello.co —— 不写 main，顶层直接读 argc/argv
int i = 1;              // 从 1 起，跳过 argv[0]（程序名）
while (i < argc)        // 以 argc 计数遍历，不靠越界试探
{
    // 处理 argv[i]（如 argv[i][0] 取首字符）……
    i = i + 1;
}
return 0;
```

若你写了显式的 `main`（C 风格），仍按 C 惯例以形参接收：`int main(int argc, char** argv)`。

> **规划中**：让 `argv` 成为**全局可见、自带长度**的字符串数组值类型（在函数、方法里也能读、无需 `argc`），依赖 Co 的数组自带长度基础设施（与 `string`/通用数组同批），尚未提供；当前以 C 形 `argc` + `char**` 先行落地。

## 没有可执行入口时

若一个程序**既没有顶层语句、又没有 `main`**（确实无事可做），而目标是生成可执行文件：编译器**给出警告**，并生成一个**什么都不做、退出码为 `0` 的空可执行文件**——构建仍算成功。生成动态库 / 静态库时不适用此规则（库本就不要求入口）。

## 跨模块的执行时机

自 **V0.3.0** 起，当一个程序由多个模块（`.co` 文件）组成、彼此 `import` 时，各模块顶层裸代码的执行遵循：

- **首次加载时执行一次**：同一模块不论被引用多少次，其顶层裸代码只跑一次。
- **集中拓序**：所有被 `import` 模块的顶层代码在主源入口之前统一执行；顺序 = 依赖闭包的 **DFS 后序**（被依赖方先跑、依赖方后跑），`import` 行的书写位置不影响执行时机。
- **非主模块的 `main` 不作为加载钩子**：若模块内定义了 `main`，它只是普通函数符号，不会自动执行。

具体规则见「import（模块导入）」与「模块」两章。

## 当前实装边界

自 **V0.2.0** 起，入口分派与退出码行为已按上述约定实装：

- 文件含顶层裸指令时，编译器合成入口、按源码顺序执行顶层；若同时存在用户定义的 `main`，所有顶层跑完后自动进入 `main`，`main` 的返回值作为退出码。
- 顶层中 `return V;` 立即结束程序、退出码为 `V`；裸 `return;` 退出码为 `0`。
- 文件既无顶层裸指令、也无 `main`：产出可执行文件时编译器告警、仍产一个什么都不做、退出码为 `0` 的空入口。
- 纯 C 写法（无顶层裸指令 + 含 `main`）仍沿用 C 入口链入行为，不进入合成入口。
- **Windows GUI 入口**（自 V0.3.1）：源里定义 `WinMain` 则取 GUI 入口（无控制台）；或入口函数标 `[[subsystem("windows")]]` 切 windows 子系统。`WinMain` 与顶层裸指令互斥、形参须 4 个。
- **命令行参数**（自 V0.5.5）：`.co` 顶层入口（合成控制台 `main`）内建 `argc`(`int`)/`argv`(`char**`)，靠 `argc` 计数遍历、`argv[argc]==NULL`；仅合成入口的顶层代码作内建名作用域内有效（`.c`/`-o *.dll`/`*.so`/`WinMain` 下引用 `argv` 报 undeclared）；若走显式 `main`（纯 C 写法）仍按形参接收 argc/argv。

尚未提供的部分：

- `argv` 作为**全局可见、自带长度**的字符串数组值类型（函数/方法内可读、无需 `argc`）尚未提供，依赖数组自带长度基础设施（D37，与 `string`/通用数组同批）；当前仅以 C 形 `argc` + `char**` 顶层内建名先行落地。
