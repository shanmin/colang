# 程序入口与执行

> 本章描述 Co 的程序入口与执行模型。**入口分派、`main` 可选、顶层 `return` 与退出码自 0.2.0 已实装；跨模块（`import`）顶层代码的集中拓序执行自 0.3.0 已实装**；命令行参数 `argv` 仍未提供（见末尾「当前实装边界」）。

## 顶层语句顺序执行

Co 的程序从「顶层」开始执行：一个 `.co` 文件里，写在函数、类型等定义**之外**的命令（顶层裸指令），**按它们在源码中出现的先后顺序**依次执行。你不必写一个 `main` 函数来充当入口。

## 有没有 `main` 都可以

为兼容 C 风格写法，Co 同时接受两种程序：

- **不写 `main`**：程序就是「顺序执行顶层语句」，执行完即结束。
- **写了 `main`**：`main` 是一个普通函数，在**所有顶层语句执行完之后**才进入它。

## 进程退出码

程序结束返回给操作系统的数（退出码）按下列规则确定：

| 情形 | 退出码 |
| --- | --- |
| 顶层执行到 `return V;` | `V`，并立即结束整个程序（其后的顶层语句与 `main` 都不再执行） |
| 顶层跑完没有 `return`，且有 `main` | `main` 的返回值 |
| 顶层跑完没有 `return`，且无 `main` | `0` |
| 裸 `return;`（不带值） | `0` |

要点：**顶层的 `return` 结束的是整个程序**（不是某个函数），因此它会**跳过 `main`**；函数体内的 `return` 仍只结束它所在的函数（见「函数定义」章节）。

## 命令行参数

命令行参数通过一个全局的 `argv` 读取：

- `argv` 是字符串数组，`argv[0]` 通常是程序自身的路径，其后依次是各参数；
- 参数个数取 `argv` 这个数组的长度（Co 的数组自带长度，无需另设计数变量）；
- `argv` 全局可见，在函数、方法里也能读。

## 没有可执行入口时

若一个程序**既没有顶层语句、又没有 `main`**（确实无事可做），而目标是生成可执行文件：编译器**给出警告**，并生成一个**什么都不做、退出码为 `0` 的空可执行文件**——构建仍算成功。生成动态库 / 静态库时不适用此规则（库本就不要求入口）。

## 跨模块的执行时机

自 **0.3.0** 起，当一个程序由多个模块（`.co` 文件）组成、彼此 `import` 时，各模块顶层裸代码的执行遵循：

- **首次加载时执行一次**：同一模块不论被引用多少次，其顶层裸代码只跑一次。
- **集中拓序**：所有被 `import` 模块的顶层代码在主源入口之前统一执行；顺序 = 依赖闭包的 **DFS 后序**（被依赖方先跑、依赖方后跑），`import` 行的书写位置不影响执行时机。
- **非主模块的 `main` 不作为加载钩子**：若模块内定义了 `main`，它只是普通函数符号，不会自动执行。

具体规则见「import（模块导入）」与「模块」两章。

## 当前实装边界

自 **0.2.0** 起，入口分派与退出码行为已按上述约定实装：

- 文件含顶层裸指令时，编译器合成入口、按源码顺序执行顶层；若同时存在用户定义的 `main`，所有顶层跑完后自动进入 `main`，`main` 的返回值作为退出码。
- 顶层中 `return V;` 立即结束程序、退出码为 `V`；裸 `return;` 退出码为 `0`。
- 文件既无顶层裸指令、也无 `main`：产出可执行文件时编译器告警、仍产一个什么都不做、退出码为 `0` 的空入口。
- 纯 C 写法（无顶层裸指令 + 含 `main`）仍沿用 C 入口链入行为，不进入合成入口。

尚未提供的部分：

- 命令行参数 `argv` 未在本版提供（无内置全局 `argv` 数组、也无数组自带长度基础设施）。
